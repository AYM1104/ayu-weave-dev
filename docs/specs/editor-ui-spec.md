# [Current] エディターページ UI仕様書

この仕様書は、`frontend/src/features/editor/` の現状実装をもとに整理した「実装準拠のUI仕様」です。  
プロダクトとして目指している仕様ではなく、今のコードで実際に何が表示され、何が操作できるかをわかりやすくまとめています。

## 1. 対象範囲

- 対象画面
  - `/album/edit`
  - `/demo/editor`
- 主な実装ファイル
  - `frontend/src/features/editor/components/*`
  - `frontend/src/features/editor/store/editorStore.ts`
  - `frontend/src/features/editor/utils/editorUpload.ts`
  - `frontend/src/lib/layouts/*`

補足:
- 既存の `docs/specs/user-flow.md` では `/album/[id]/edit` を想定しているが、現状の Next.js ルートは `/album/edit`。
- 写真アップロードの API 連携で使う `albumId` は、ルートパラメータではなくクエリ文字列 `?id=` から取得している。

## 4. 領域ごとの仕様

### 4.1 ヘッダー

役割:
- 画面上部中央の `menu` ボタンだけを表示する
- グローバルメニューの開閉を担当する

見た目:
- ガラス風の半透明ボタン
- ラベルは `menu`
- 開いている間は `CloseIcon`、閉じている間は `MenuIcon`

操作:
- ボタン押下でメニュー開閉
- メニュー表示中は透明な全画面 scrim を出す
- `Escape` キーで閉じる
- scrim クリックで閉じる

メニュー項目:

| 項目 | 遷移先 / 動作 |
|---|---|
| 新規アルバム | `/album/upload` |
| 下書き | `/dashboard` |
| 注文履歴 | `/account/orders` |
| ログアウト | `/login` へ `router.push()` |

補足:
- 現状はアルバムIDを引き継がない。
- メニューは `role="dialog"` と `aria-modal="true"` を付与している。

### 4.2 左サイドバー

役割:
- レイアウトテンプレートの選択
- 今どちらのページを編集対象としているかの表示

表示要素:

1. テンプレート情報カード
   - タイトル: `テンプレートを使用`
   - サブテキスト: `全3タイプ`

2. レイアウトカテゴリのプルダウン
   - 初期値: `全てのレイアウト`
   - 選択するとカテゴリを絞り込む

3. 編集対象ラベル
   - 表示例: `編集対象: 表紙` / `編集対象: 左ページ` / `編集対象: 右ページ`

4. カテゴリ別アコーディオン
   - 初期状態では全カテゴリが開いている

現状表示されるカテゴリ:

| カテゴリ | テンプレート数 |
|---|---|
| 見開き | 3 |
| 1枚 | 10 |
| 2枚 | 3 |
| 3枚 | 2 |
| 多枚数 | 2 |
| テキスト | 2 |

合計:
- 実際に選択可能なテンプレートは `22` 個

操作仕様:
- サムネイルクリックでレイアウトを適用する
- 単ページレイアウトなら現在の編集対象ページだけに適用する
- `見開き` カテゴリのレイアウトを本文ページで選ぶと、その見開きの左右2ページへ同時適用する
- レイアウト変更時は `selectedSlotId` / `selectedSlotPageIndex` をリセットする
- レイアウト変更時は新しいテンプレートの `slots` をそのまま複製するため、既存の写真割り当てはクリアされる

重要な挙動:
- カテゴリの選択肢はページ文脈に応じて制限されない
- そのため、表紙編集中でも `見開き` レイアウトを選べてしまう
- 表紙で見開きレイアウトを選ぶと、右半分だけを使う不自然な表示になる

### 4.3 コントロールバー

役割:
- 画面上部の主要操作ボタンを配置する

左側:
- Undo ボタン
- Redo ボタン

右側:
- `プレビュー`
- `カートに入れる`

現状仕様:
- Undo / Redo は常に `disabled`
- `プレビュー` と `カートに入れる` は見た目だけで、クリック時の処理は未実装

### 4.4 中央キャンバス

役割:
- 現在の見開きページを大きく表示する
- ページやスロットを選択する
- 前後の見開きへ移動する

#### 見開きの考え方

`pages` 配列はページ単位で持つが、UI上は見開き単位で扱う。

| spreadIndex | 表示内容 |
|---|---|
| 0 | 左なし + 右に表紙 (`page 0`) |
| 1 | `page 1` + `page 2` |
| 2 | `page 3` + `page 4` |
| ... | 以降同様 |

補足:
- 最後の見開きで右ページが存在しない場合は、左ページだけを編集対象にする

#### 見開き移動

- 左右の矢印ボタンで前後移動
- 最初の見開きでは `prev` 無効
- 最後の見開きでは `next` 無効
- 見開き移動時は選択中スロットを解除する

#### ページ選択

- 左ページ / 右ページ自体がクリック可能
- 選択中ページにはアウトラインを表示
- `Enter` / `Space` でも選択できる

選択ルール:
- 表紙見開き (`spreadIndex = 0`) では右ページだけが編集対象
- 右ページが存在しない見開きでは自動的に左ページを編集対象にする

#### 写真スロット表示

- 各レイアウトの `slots` を絶対配置で描画
- 写真が入っていれば `img` を `object-fit: cover` で表示
- 写真ステータスが `ready` 以外なら下部に状態ラベルを重ねる
  - `アップロード中`
  - `画像処理中`
  - `エラー`

スロット状態:
- hover: 薄い枠線
- active: hover中の枠線
- selected: 濃い枠線

キーボード操作:
- 各スロットは `role="button"` と `tabIndex=0` を持つ
- `Enter` / `Space` で選択できる

#### 見開きレイアウト特有の挙動

- 左右ページが同じ見開きレイアウトIDを持つ場合、1つの見開きレイアウトとして扱う
- 見開きスロットは左右ページに分割して表示する
- 同じスロットIDは左右で連動する
  - hover も連動
  - selected も連動
  - 写真配置も連動

#### 比率ラベル

- 単ページ表示では中央に `1:1` または `4:3` のラベルを出す
- 見開きレイアウト時は見開き中央に `4:3` を出す

#### ズーム

- ズームはページの描画サイズにのみ反映する
- 100% 時の1ページサイズは `439 x 620`
- 70% 初期表示では約 `307 x 434`

### 4.5 フッター

役割:
- 見開き一覧のナビゲーション
- ズーム変更
- 表示モード切り替え

表示要素:

1. 見開きサムネイル一覧
   - 横スクロール
   - 1見開きごとにサムネイル表示
   - 先頭だけラベル `表紙`
   - それ以外は左ページ番号を表示

2. カスタムスクロールバー
   - サムネイル列のスクロール位置と同期
   - ドラッグ可能
   - スクロール中だけ表示され、約 `700ms` 後に消える

3. ズームスライダー
   - `30%` 〜 `150%`
   - 現在値を右端に数値表示

4. ページカウンター
   - 表示形式: `currentSpreadIndex / maxSpread`
   - 例: `1 / 15`

5. 表示切り替えボタン
   - `グリッド表示` / `見開き表示` をトグル

重要な挙動:
- サムネイルクリックで `goToSpread()` を実行
- `viewMode` の state は更新される
- ただし、現状の画面描画は `viewMode` を参照していないため、UIは何も変化しない

### 4.6 右サイドバー

役割:
- 写真アップロード
- 写真一覧の閲覧
- 写真のページスロットへの配置

右サイドバーは、写真が0枚かどうかで表示が切り替わる。

#### A. 写真が0枚のとき

表示内容:
- 大きなアップロードエリア
- QRコード案内エリア

アップロードエリア:
- クリックでファイル選択ダイアログを開く
- `Enter` / `Space` でも開ける
- ドラッグ&ドロップ対応

案内文:
- `ドラッグ&ドロップ`
- `または`
- `ファイルを開く`
- `アップロード可能フォーマット: JPG, PNG`
- `1回のアップロードで50MBまで`

QRエリア:
- サンプル画像 `/images/qr-code-sample.png`
- 文言 `スマホからアップロードもできます`

#### B. 写真が1枚以上あるとき

表示内容:
- フィルタセレクト
- 比率別の写真セクション
- アップロード進捗フッター

フィルタ:

| 値 | 意味 |
|---|---|
| すべての写真 | 全件表示 |
| 未使用の写真 | `used = false` |
| 使用中の写真 | `used = true` |

写真のグルーピング:
- `aspectRatioLabel` ごとにセクション分け
- 並び順は `1:1` → `4:3` → `3:2` → `16:9` → `その他`

各セクション:
- ヘッダークリックで開閉
- 初期状態は開いている
- 写真カードは2カラム表示

写真カードの見え方:
- 通常: 正方形サムネイル
- `used = true`: 内側ボーダー表示
- `status = processing / error`: 状態ラベルを重ねる
- `error` またはサムネイルなし: クリック不可

追加導線:
- 写真が1件以上あるときは、一覧下部に `画像をアップロード` ボタンを表示する
- クリックするとファイルダイアログを開く

空状態:
- フィルタ結果が0件の場合は `表示できる写真がまだありません`
- この空状態もクリック / キーボードでアップロードを開始できる

#### 写真アップロード仕様

受け付けるファイル:
- `.jpg`
- `.jpeg`
- `.png`
- MIME type は `image/jpeg`, `image/png`
- 1ファイルあたり `50MB` 以下

バリデーション:
- 非対応形式は拒否
- サイズ超過は拒否
- エラー表示は `window.alert()` で先頭1件だけを表示

アップロードの流れ:
1. ファイルごとにローカルのドラフト写真を作成
2. 一覧へ即時反映
3. 画像サイズを読んで `aspectRatioLabel` を付与
4. API有効時は本アップロード、無効時はデモアップロード
5. 進捗を下部フッターへ表示
6. 完了後、`ready` または `processing` / `error` に更新

API有効条件:
- `NEXT_PUBLIC_API_URL` がある
- URLクエリに `id` がある

API有効時の追加挙動:
- 画面表示時に既存写真を取得する
- 画像処理が終わっていない場合はポーリングで状態を確認する

API無効時:
- 擬似進捗を出すデモアップロードになる

アップロード進捗フッター:
- `アップロード中...`
- `完了件数 / 総件数`
- 進捗バー
- `アップロードを中止` ボタン

中止時:
- 進行中のアップロードを全件 abort する
- 中止されたドラフト写真は一覧から削除される

#### 写真配置仕様

写真カードクリック時の配置ルール:
1. 選択中スロットがあれば、そのスロットへ配置
2. なければ現在ページの最初の空スロットへ配置
3. 空スロットがなければ、最初のスロットを上書き

見開きレイアウト時:
- 実際の配置元ページは見開き左側ページとして扱う
- 同じスロットIDを左右に同期する

重要な挙動:
- `used` は「どこか1箇所以上で使われている」ことを示すだけ
- 既に使っている写真を別スロットへ再利用することは可能
- つまり、同じ写真を複数スロットへ重複配置できる

## 5. 状態管理の整理

主要 state:

| state | 初期値 | 意味 |
|---|---|---|
| `pages` | `mockPages` | アルバムの全ページ |
| `layouts` | `ALL_LAYOUTS` | 全テンプレート |
| `photos` | `mockPhotos` | 写真一覧。初期は空 |
| `currentSpreadIndex` | `1` | 表示中の見開き |
| `selectedPageSide` | `right` | 編集対象の左右 |
| `selectedSlotId` | `null` | 選択中スロットID |
| `selectedSlotPageIndex` | `null` | 選択中スロットの属するページ |
| `selectedLayoutCategory` | `全て` | 左サイドバーの絞り込み |
| `zoomLevel` | `70` | キャンバス倍率 |
| `viewMode` | `spread` | 見開き/グリッドの表示モード |

state 更新時の代表ルール:
- 見開き移動でスロット選択解除
- ページ左右切り替えでスロット選択解除
- レイアウト適用でスロット選択解除
- 写真配置 / レイアウト変更 / 写真削除後に `used` を再計算

## 6. 典型的なユーザーフロー

### 6.1 ページを切り替える

1. 左右の矢印、またはフッターのサムネイルを押す
2. `currentSpreadIndex` が変わる
3. 選択中スロットが解除される
4. 新しい見開きが表示される

### 6.2 レイアウトを変える

1. 左サイドバーでカテゴリを選ぶ
2. サムネイルを押す
3. 現在の編集対象ページ、または見開き全体へレイアウトを適用
4. 既存の写真割り当ては消える

### 6.3 写真を追加する

1. 右サイドバーでドロップ、またはクリック
2. 画像ドラフトが一覧に追加される
3. 進捗表示が始まる
4. 完了後にカードとして利用可能になる

### 6.4 写真を配置する

1. キャンバス上でページまたはスロットを選ぶ
2. 右サイドバーの写真カードを押す
3. 選択中スロット、または空スロットへ自動配置される
4. 見開きレイアウトなら左右に同期される

## 7. 既存仕様との差分と注意点

この章は、今後の改善時に見落としやすい点をまとめたもの。

- `docs/specs/user-flow.md` では左パネルに「ページ数・表紙素材・カラー変更」がある前提だが、現状実装はレイアウト選択のみ
- 同ドキュメントではアップロード完了やエラーをトースト通知する想定だが、現状は `window.alert()` と `console.error()` が中心
- ルートは `/album/edit` で、`/album/[id]/edit` ではない
- API連携用の `albumId` はクエリ文字列依存
- Undo / Redo は未実装
- プレビューは未実装
- カート導線は未実装
- `viewMode` は state だけ存在し、見た目は切り替わらない
- 右サイドバーに写真削除UIはない
- 同じ写真の重複配置を防いでいない
- 表紙にも見開きレイアウトを適用できてしまう
- 左上カードの `全3タイプ` は現状実装と不一致。実際は6カテゴリ・22テンプレート
- `mockPages` には現在存在しないレイアウトIDが11件分含まれており、そのページはレジストリ先頭レイアウトへフォールバックする
- メインの3ペインには専用のレスポンシブ再構成がなく、モバイル向け最適化は未整理

## 8. この画面を今後仕様化するときの基準

今後デザインや要件を詰めるときは、まず以下を分けて決めると整理しやすい。

1. 現状維持する挙動
   - 見開き単位のナビゲーション
   - 左右ページ選択
   - 右サイドバーからの即時配置

2. 明確に未完成な挙動
   - Undo / Redo
   - プレビュー
   - カート導線
   - グリッド表示
   - トースト通知
   - レスポンシブ対応

3. 仕様を再定義した方がよい挙動
   - 表紙での見開きレイアウト許可有無
   - レイアウト変更時に写真を保持するかどうか
   - 同一写真の複数配置を許可するかどうか
   - ルート設計を `/album/[id]/edit` に寄せるかどうか
