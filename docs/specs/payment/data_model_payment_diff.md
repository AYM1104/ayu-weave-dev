# data_model 決済対応版 差分サマリー

> `data_model.md`（元版）と `data_model_payment.md`（決済対応版）の変更点をまとめたドキュメントです。
> 詳細な変更理由は `plan_feedback.md` も参照してください。

---

## 1. フェーズ構成の明示化【追加】

v1 では「Phase 1 / Phase 2」の2段階だったが、v2 ではサブフェーズを追加。

| フェーズ | v1 | v2 |
| --- | --- | --- |
| Phase 1 | フォトブック編集・保存 | 同左（変更なし） |
| Phase 2 | 決済 + 印刷連携（混在） | Phase 2-1：Stripe基本決済 |
| Phase 2（続き） | 〃 | Phase 2-2：印刷ベンダー連携・発送 |

**理由：** 「Phase 2」という表現だと決済と印刷連携のどちらを指すか曖昧。両機能を分離して実装タイミングを明確にするため。

## 2. `orders` テーブル【カラム変更・追加・削除】

### カラム名の変更（リネーム）

| v1 カラム名 | v2 カラム名 | 理由 |
| --- | --- | --- |
| `checkout_session_id` | `stripe_checkout_session_id` | どのサービスのIDか名前だけで判別できるようにするため |
| `payment_intent_id` | `stripe_payment_intent_id` | 同上 |

また `stripe_checkout_session_id` には **UNIQUE 制約を追加**。1注文に対してSessionが複数紐づく設計ミスを防ぐため。

### カラムの追加

| カラム名 | 内容 | 備考 |
| --- | --- | --- |
| `amount_jpy` | 注文金額（税込・日本円） | 料金体系未確定のため Phase 1 では NULL。設定ロジックは Phase 2-1 |
| `currency` | 通貨コード（'JPY' 固定） | 将来の多通貨対応に備えてカラムのみ定義 |

### カラムの削除

| v1 カラム名 | 削除理由 |
| --- | --- |
| `image_cleanup_needed` | `order_events` テーブルのイベント履歴で代替できるため。専用フラグは二重管理になりズレが生じるリスクがある |

### 追加しないカラム

| カラム名 | 理由 |
| --- | --- |
| `shipping_address` | 個人情報は自社DBに持たない方針。Stripe Checkout Session に保持し、発注時（Phase 2-2）に Stripe API から都度取得する |

## 3. `order_events` テーブル【新規追加】

v1 には存在しなかった。

**目的：**
- `image_cleanup_needed` フラグのような「状態フラグ」の代替（追加＆参照しやすいイベントログ）
- CS対応時に「この注文はいつどうなったか」を時系列で確認できる
- 将来の監査ログ・トラブルシュートの基盤

**実装タイミング：** スキーマは Phase 1 で作成。書き込みロジックは Phase 2-1（決済イベント受信時）から開始。

---

## 4. `stripe_processed_events` テーブル【新規追加】

v1 には存在しなかった。

**目的：** Stripe の Webhook 二重処理を防ぐ（冪等性の保証）。
Stripe Event ID を主キーとして保存することで、DB 制約レベルで重複処理を防ぐ。

```
Webhookが届く
  ↓
stripe_processed_events に この event_id が存在する？
  → Yes: スキップ（二重処理を防ぐ）
  → No:  処理を実行 → event_id をテーブルに保存（主キー制約で重複INSERTは自動エラー）
```

**実装タイミング：** スキーマは Phase 1 で作成。書き込みロジックは Phase 2-1 で実装。

## 5. `OrderStatus` の `draft` の扱い【変更】

| | v1 | v2 |
| --- | --- | --- |
| Phase 1 での扱い | 実装する | enum定義のみ（遷移ロジックは Phase 2-1） |

**理由：** Phase 1 は決済機能を含まないため、注文レコード自体を作成しない。スキーマだけ定義しておく。

## 6. 個人情報取り扱い方針セクション【新規追加】

v1 には存在しなかった（`orders` テーブルの注記として断片的に記載されていた）。

v2 では独立したセクションとして明示。

**基本方針：** 「個人情報は最小限かつ期限付きで保持する」

**主な規定：**
- 配送先住所：自社DBに**保存しない**。Stripe API から都度取得。
- メールアドレス：users テーブルに保持（必須）。退会時に削除。
